/steer in the Claude Code app

No terminal, no VS Code. You type into the app the way you already do.

You hand an agent a job and it comes back with fourteen changed files. /steer writes your ask down as a numbered row first, then places each change against it, on your own machine, so you can see which change left the lane before you read the diff.

One command to set it up

Open the Claude Code app, pick your project folder, and paste this into the chat:

Run this for me: npx thetacog-mcp

Claude runs it and puts the skills (/steer, /steer-every, /rewrite, /licence and the rest) into ~/.claude/skills, the folder the app reads in every project. This page opened because that ran.

Then use it

Start a new session in the app (the skills load at the start of a session), and type:

/steer add a refunds endpoint that never refunds more than the charge

Your first ask creates docs/specs/vna/SPEC-VNA-COCKPIT.md in your project, with your words as row C1. /steer splits an ask that carries several jobs into one row each, and shows you the rows before any of them run.

Already deep in a conversation? Dump it into /steer

You do not have to start clean. In the session where you and Claude have been talking for an hour, type:

/steer everything we decided in this conversation

Or paste a conversation from somewhere else after /steer. The whole conversation is one ask that carries many jobs, so /steer splits it into one numbered row per job, each in your own words, and writes the rows to docs/specs/vna/SPEC-VNA-COCKPIT.md. You read the rows. Then a worker takes them one at a time, one commit per row, and each commit is placed against the row that ordered it. The chat stops being the only record of what you asked.

How /steer works, from your ask to the receipt

  1. You type the ask in your own words. /steer add a refunds endpoint that never refunds more than the charge
  2. The ask is compiled into one file. npx thetacog-mcp steer-compile "<your ask>" writes .thetacog/steers/<date>-<slug>.txt: one row per job in the ask, a proposed guard (the test that fails until the job is done), whose act each row is (yours or the worker's), the nearest rows already in your spec, and one goal line.
  3. The rows are declared in your spec. They land in docs/specs/vna/SPEC-VNA-COCKPIT.md before any work starts, so the record of what you asked exists before the record of what was done.
  4. A worker takes each row. The worker is a background claude session that boots from the row, never from the chat. Your session stays free while it runs.
  5. Each commit is placed against the row that ordered it. The walk reads the commit from git and places it: in lane, flagged, or a breach, with a receipt anyone can rerun from the same commit and get the same answer. No model sits in that step.
  6. You read one line, not fourteen files. The Δ line names where the work landed and how far it sits from what you declared. The halt stays yours to wire: /steer records and places, and you decide.

What it can tell you: WHERE the work landed against what you declared, re-runnable from the commit. What it cannot: WHETHER the code is bug-free. That is undecidable (Rice, 1953), and /steer never claims it.

Every skill this install gave you

Each card below is read off that skill's own SKILL.md on your machine at install, so this page matches what you have. Type the slash command in a new Claude Code session; the doors are the commands the skill runs for you.

The skill cards are written in when the package installs. On GitHub, each skill's full text is in skills/.

What you need

  • Node 20 or newer on the machine. If the command answers npx: command not found, install Node from nodejs.org and paste the line again.
  • The Claude Code app on your Mac, working on a local folder. A cloud session reads its own skills folder, never the one on your machine.
  • Nothing else for the plan and the receipt: no account with us, no key, no database.

When a row runs in the background

A row that dispatches hands its work to a background worker, which is the claude command. When the run answers ENGINE_BINARY_MISSING: claude, ask Claude in the app:

Run this for me: npm i -g @anthropic-ai/claude-code

Then ask again. Nothing dispatched before the worker existed, so nothing half-ran.

If something looks wrong

  • npx thetacog-mcp skills --debug prints every skill's state and opens a report page with the versions it found.
  • A SKILL.md someone else wrote at the same path is left alone and named, never overwritten.
  • To skip the skills next time, set THETACOG_NO_SKILLS=1. To keep this page from opening, set THETACOG_NO_OPEN=1.
